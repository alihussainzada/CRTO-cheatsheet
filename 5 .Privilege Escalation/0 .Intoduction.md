	scPrivilege escalation is a tactic [TA0004] by which they attempt to exploit a vulnerability or misconfiguration to gain additional privileges.  This is often a necessary prerequisite to carrying out additional tactics, such as [credential access](https://www.zeropointsecurity.co.uk/path-player?courseid=red-team-ops&unit=674b78a7d9f99e969c066ebf).

## Windows Accounts
There are three main account groups which are relevant to privilege escalation.

| Account        | Privileges / Behaviour                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| Users          | Low privilege; generally limited to their own files.                                                    |
| Administrators | Local Administrators group; Full Control over most objects, including files, directories, and services. |
### 3. Service User Accounts
These accounts are built into Windows and are used by the Service Control Manager (SCM) to run many of the services that Windows relies on.  These are:

| LocalService (`LOCAL SERVICE`)     | Minimal local privileges; uses anonymous credentials for network authentication.                                                              |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| NetworkService (`NETWORK SERVICE`) | Minimal local privileges; authenticates on the network using the computer's credentials.                                                      |
| LocalSystem (`SYSTEM`)             | Full Control over most system objects, similar to Administrators. May have additional privileges; generally the highest Windows access level. |
## User Rights Assignment
Windows security policies that provide fine-grained control over account privileges. Services may need more privileges than standard users but fewer than administrators.

|Type|Purpose|Example|
|---|---|---|
|Logon Rights|Control how and where an account can log on.|`SeBatchLogonRight` allows logon by batch services, such as Task Scheduler.|
|User Rights|Control access to objects and may override explicit permissions.|`SeBackupPrivilege` allows reading any file, even without explicit read permission.|
Privilege escalation risk: Sensitive rights such as `SeImpersonatePrivilege` can be abused to obtain SYSTEM privileges. These rights may be assigned to service accounts running web or SQL servers.

## Vulnerable Services
Windows services are a major privilege-escalation attack surface because they often run as `SYSTEM` and may be vulnerable or misconfigured.

Common weaknesses:

| Vulnerability                          | MITRE ATT&CK |
| -------------------------------------- | ------------ |
| DLL Search Order Hijacking             | `T1574.001`  |
| PATH Environment Variable interception | `T1574.007`  |
| Search Order Hijacking                 | `T1574.008`  |
| Unquoted Service Path                  | `T1574.009`  |
| Weak Service File Permissions          | `T1574.010`  |
| Weak Service Registry Permissions      | `T1574.011`  |
| Generic software vulnerabilities       | `T1068`      |
### Enumerating Services
Built-in tools and methods:
- CMD: `sc.exe`, `wmic.exe`
- PowerShell: `Get-Service`, `Get-WmiObject`
- Windows API: `EnumServicesStatusEx`
- Beacon: `sc_enum`
